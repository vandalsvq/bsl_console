# help-hbk-form: план реализации и решения

Транзиентный спутник [`spec.md`](spec.md).

## 1. План реализации

### Этап 1. Разметка формы (`Form.xml`)

- Группа `ГруппаНастроекСправка` внутри существующей `Настройки` (рядом с `ГруппаНастроек1..3`).
- Реквизиты формы (свободные id ≥ 27): `ФайлСправки1С` (строка, `<Save>`),
  `ЗагружатьСправкуПриОткрытии` (булево, `<Save>`), `СостояниеСправки` (строка).
- Элементы (свободные id ≥ 93): `InputField ФайлСправки1С` (`ChoiceButton`, событие `StartChoice`),
  `CheckBoxField ЗагружатьСправкуПриОткрытии`, `Button ЗагрузитьСправку`,
  `LabelDecoration СостояниеСправкиНадпись`.
- Команда `ЗагрузитьСправку` (свободный id ≥ 31).
- Gate: `load_form.ps1` собирает epf без ошибок (exit 0) — форма валидна.

### Этап 2. Код формы (`Module.bsl`, область `СправкаHBK`)

- `НайтиФайлСправки()` — `КаталогПрограммы()` → соседние каталоги версий (сортировка по убыванию).
- `ФайлСправки1СНачалоВыбора` — `ДиалогВыбораФайла(Открытие)`, фильтр `*.hbk`.
- Конечный автомат передачи на `ПодключитьОбработчикОжидания`: очередь пакетов
  (`shlang` → `shcntx`), в каждом — чтение порций `ЧтениеДанных` → `Base64Строка` →
  `pushBase64Chunk`, затем `endBase64Transfer` + `parseHelp`.
- Индикация в `Элементы.СостояниеСправкиНадпись.Заголовок`.
- Врезки: `ПриСозданииНаСервере` (восстановление настроек), `ИнициализацияРедактора` (автостарт).
- Gate: сборка epf + ручной прогон в поле владельцем.

Код области хранится в репозитории копией — [`form_module_fragment.bsl`](form_module_fragment.bsl)
(в самой обработке он живёт внутри `.epf`, вне контроля версий).

### Этап 4. Гейт компиляции формы (не делаем)

Сборка epf (`LoadExternalDataProcessorOrReportFromFiles`) модуль **не компилирует** — заведомо
сломанный текст даёт exit 0, ошибка всплывает только при открытии формы. `/CheckModules` по каталогу
с `.epf` тоже пустышка: ключ игнорируется, проверяется пустая конфигурация (сверено с заведомо
неверным ключом — ответ тот же). Рабочая идея — заворачивать форму во временную конфигурацию:
обработка без формы грузится (exit 0), с формой `LoadConfigFromFiles` падает на
`Исключение XDTO при чтении Ext/Form.xml`, причём и на нетронутой форме автора — значит дело
в конвертации epf→конфигурация, а не в наших правках. Скрипт — `scratchpad\check_form_module.ps1`.

### Риски и снижение

- **40 МБ через мост.** Порции по 1 МБ, пачками по таймеру; при провале — уменьшить порцию/пачку.
- **Отзывчивость формы.** Читаем и отдаём порции только в обработчике ожидания, не в цикле.
- **`Base64Строка` вставляет переводы строк.** По контракту моста пробельные символы игнорируются.
- **Разная разрядность/версии платформы.** Поиск не привязан к конкретной версии: берём
  `КаталогПрограммы()`, затем перебираем каталоги установки.

### Этап 4. Ревизия под релизы автора 0.5.4/0.5.5 и 0.3.8/0.3.9 (22.08.2026)

Автор переписал свою обвязку: в `console.epf` 0.5.5 загрузка справки идёт асинхронно
(`Асинх` / `Ждать`, `НайтиФайлыАсинх`, `РазмерАсинх`, `ПрочитатьАсинх`, `ЗакрытьАсинх`), грузятся
`shcntx` и `shquery`, а рядом появился большой блок 1С:Напарника (AI inline-подсказки). Наша прежняя
форма была форком более старой авторской и от неё отстала.

Решение владельца — «забирать всё»: **базой стала форма автора** из релиза, а наши добавки лёгли
поверх:

- область `СинтаксисПомощник` целиком наша (настройка пути + автопоиск по соседним версиям
  платформы, автозагрузка при открытии, прогресс, все четыре пакета), но на 0.55 — в асинхронном
  стиле автора, на 0.20 — прежняя тактовая (там `Асинх` нет);
- ветки `EVENT_ON_HELP_PREPARED` / `EVENT_ON_HELP_READY` показывают вид пакета (`kind` читается
  через `Попытка`: `params` приходит объектом браузера, а не структурой 1С);
- тумблер режима сравнения (кнопка «Сравнить с оригиналом» остаётся видимой и выключает сравнение
  повторным нажатием) — вместо авторского сокрытия командной панели;
- макет `src` — наша сборка `build:pack` соответствующей ветки.

Гейты ревизии: `npm test`, `build:pack` + `check:workers`, `escheck`, `test:headless`,
`build:test` + `test:mocha` (201/201) на 0.55; `npm test`, `build` + `escheck`, `build:pack` на 0.20;
статический линт модуля формы (баланс конструкций, цепочки на `Новый`, одноимённые процедуры) и
сквозной пробник справки на реальных `.hbk` платформы.
