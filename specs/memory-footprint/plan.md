# memory-footprint: план исследования и решения

Транзиентный спутник трека. Стабильных контрактов трек пока не меняет, поэтому `spec.md` не заводим —
он появится, если решим менять публичный контракт (кандидат: экспорт `disposeConsole()`).

Как ведём трек:

- **гипотеза → метод → числа** пишутся в [`research.md`](research.md), каждое направление своим разделом;
- **что выбрали и почему** — в журнал решений внизу этого файла;
- **итог для человека** — в [`result.md`](result.md);
- **текст для автора** — в [`issue.md`](issue.md).

Правило, выведенное на своей шкуре (см. решение от 22.08 про Enter-стресс): полевой замер
засчитывается только с **нормировкой на счётчик** (правки, вызовы подсказок, обращения за
метаданными), иначе Working Set скачет на ±150 МБ сам по себе и любая версия «подтверждается».

## 1. Направления

Порядок — по величине рычага. Каждое направление закрывается либо числом, либо явным «не подтвердилось».

### Этап 1. Возврат памяти при закрытии формы (655–884 МБ) — СЛЕДУЮЩИЙ

Платформа при закрытии формы сносит контекст поля не полностью: после «пустого» открытия оседает
452 МБ, после рабочей сессии — 884 МБ, после четырёх форм — 655 МБ. Гипотеза: контекст можно снести
самим — переустановкой содержимого поля (`Документ.location = "about:blank"` либо очисткой реквизита
`HTML`) в `ПередЗакрытием`/`ПриЗакрытии` формы.

- Шаги: правка модуля формы в диагностической epf → полевой замер «до закрытия / после закрытия»
  на том же сценарии, что в §2.0 `research.md`.
- Gate: возвращается ли осевшее. Успех — если после закрытия формы клиент откатывается к базе ±50 МБ.
- Цена: правка только в форме, редактор не трогаем.
- Риск: платформа может не отпускать контекст в принципе — тогда направление закрывается как
  «вне нашего контроля», и остаётся только B1 (один экземпляр на приложение).

### Этап 2. Почему открытый модуль стоит 131 МБ

Модуль 509 КБ / 312 тыс. символов в поле даёт +131 МБ, в Chrome — +21 МБ. Разница в шесть раз при
том, что базовый экземпляр отличается втрое, — значит за текст платится непропорционально.

- Кандидаты: токенайзер BSL (состояние по строкам), наши парсеры при загрузке (свёртки, дерево
  переменных, поиск запросов), мост (текст идёт через реквизит формы в UTF-16, то есть ×2 уже на входе).
- Шаги: счётчики в диагностическую сборку (время и память до/после `setText`, отдельно — после
  первой полной токенизации), замер на модулях разного размера (100 КБ / 500 КБ / 2 МБ) → кривая.
- Gate: линейность и коэффициент. Если ×250 от размера текста — искать конкретного виновника.

### Этап 3. Ленивые словари (A2)

`bslGlobals` — 2 035 379 символов, материализуется всегда, даже если консолью не пользовались.
В Chrome словари стоят 19 МБ; по пропорции поля — порядка 60 МБ.

- Шаги: PoC «хранить строкой JSON, парсить при первом обращении» + `bslQuery`/`bslDCS` только в
  режиме запроса/СКД → замер «открыл и не трогал» и «открыл и вызвал подсказку».
- Gate: экономия на сценарии «открыл и не трогал» ≥ 30 МБ в поле при отсутствии заметной задержки
  на первой подсказке.
- Риск: средний — трогает горячий путь подсказок.

### Этап 4. `disposeConsole()` на `window` (A5)

Дать 1С корректно свернуть редактор перед закрытием формы: редактор, модели, воркеры, таймеры, кэши.
Ценность не столько в мегабайтах (в Chrome возвращалось 10 МБ из 147), сколько в предсказуемости и
в связке с Этапом 1.

- **Меняет публичный контракт** → перед реализацией завести `spec.md` и согласовать с мейнтейнером.

## 2. Открытые вопросы

- Отправляем ли фикс утечки автору и когда — решение отложено (22.08). До решения живёт на
  `local/webpack`.
- Автозагрузка синтакс-помощника (+763 МБ на экземпляр) включена в нашей форме по умолчанию.
  Менять ли значение по умолчанию у себя и предлагать ли автору — отдельный разговор, в `issue.md`
  намеренно не вошло.
- Нужен ли `memstat` как постоянный инструмент под флагом сборки. Пока собирается временным патчем
  поверх `src/editor.js`, в репозиторий не вносился.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-08-22 | Справку (HBK) исключить из области оптимизации | В сценарии PrintWizard файл `.hbk` не подаётся; без файла подсистема стоит 1–2 МБ. Замеры оставлены справочно |
| 2026-08-22 | Мерить в поле, а не только в Chrome | Утечка diff-моделей в Chrome почти не видна (модели шарят строки, GC работает): 3.5 МБ на 120 срабатываний против 4.1 МБ на одну правку в поле |
| 2026-08-22 | Стресс «зажать Enter» признан негодным | Дебаунс 50 мс схлопывает автоповтор в считанные вызовы: 20 секунд дали −27 МБ, и это едва не увело в вывод «утечки нет». Нагрузку строить с паузами |
| 2026-08-22 | Версия «виновата обвязка метаданных» снята | Счётчики показали: 7 обращений, 65 тыс. символов от 1С, `bslMetadata` +56 КБ. Сотен мегабайт там нет |
| 2026-08-22 | A/B делать двумя сборками с одинаковыми счётчиками | Одиночные замеры Working Set скачут на ±150 МБ; только нормировка на `EVENT_CONTENT_CHANGED` дала однозначный результат |
| 2026-08-22 | Утечку diff-моделей чинить переиспользованием модели, а не только `dispose()` прежней | `dispose()` убирает удержание, но оставляет churn: копия текста на каждую правку. Переиспользование снимает и то и другое |
| 2026-08-22 | Наши доработки увести на `local/webpack`, `webpack` держать зеркалом upstream | Чтобы ветка под PR отпочковывалась от чистого upstream и дифф был узким |
