## Симптом

При встраивании консоли в прикладное решение память клиента 1С растёт по ходу работы и не
возвращается при закрытии формы. На модуле в 300 тыс. символов — порядка **4 МБ на каждую правку
текста**; за час работы это гигабайты. Закрытие формы возвращает лишь часть: «Поле HTML документа»
живёт внутри процесса клиента (отдельного процесса рендерера нет), и платформа контекст сносит
не полностью.

## Где

`src/editor.js`, функция `calculateDiff()`:

```js
window.diffEditor.setModel({
  original: monaco.editor.createModel(window.editor.originalText),
  modified: window.editor.getModel()
});
```

Функция висит на `onDidChangeModelContent` (дебаунс 50 мс), то есть вызывается практически на
каждое изменение текста. На каждый вызов создаётся новая `TextModel` с полной копией оригинала,
а прежняя не удаляется — Monaco модели сам не диспозит. Условие срабатывания: задан оригинальный
текст (`setOriginalText`) и включены diff-декорации, то есть штатный режим консоли с отслеживанием
изменений.

## Замеры в поле

Две сборки, отличие — только это изменение. Платформа 8.3, тонкий клиент, файловая база,
модуль 312 тыс. символов. Сценарий: N циклов «символ → точка → `Esc` → два `Backspace`» с паузами
(быстрая долбёжка не показательна — дебаунс схлопывает очередь изменений).

| | без исправления | с исправлением |
| --- | --- | --- |
| правок текста | 31 | 81 |
| моделей Monaco: до → после | 3 → **34** | 2 → **2** |
| Working Set: до → после, МБ | 666.4 → 793.0 | 722.7 → 668.7 |
| Private bytes: до → после, МБ | 611.6 → 753.1 | 667.3 → 604.3 |
| Δ памяти | **+126.6 МБ** | **−54.0 МБ** |
| цена одной правки | **4.1 МБ** | 0 |

Утёкших моделей ровно столько же, сколько правок (31 правка → +31 модель). Вес копии равен весу
открытого модуля: 312 тыс. символов ≈ 4.5 МБ на модель с токенизацией.

В Chrome утечка почти не видна (модели шарят строки, GC работает исправно): на 120 срабатываний
прирост heap 3.5 МБ. Поэтому нужен полевой замер — браузерных пробников недостаточно.

## Предлагаемое исправление

Не пересоздавать `original`-модель, когда пересоздавать нечего: если оригинал и модель редактора
не менялись, diff пересчитается сам по изменению `modified`-модели. При реальной смене — снимать
прежнюю модель.

```js
let previous = window.diffEditor.getModel();

let reusable = previous
  && previous.original && !previous.original.isDisposed()
  && previous.modified === window.editor.getModel()
  && window.diffEditor.originalTextRef === window.editor.originalText;

if (!reusable) {

  window.diffEditor.setModel({
    original: monaco.editor.createModel(window.editor.originalText),
    modified: window.editor.getModel()
  });

  window.diffEditor.originalTextRef = window.editor.originalText;

  if (previous && previous.original && !previous.original.isDisposed())
    previous.original.dispose();

}
```

Заодно в том же PR — три временные модели, которые создаются только ради `getFullModelRange()`
и остаются висеть: `selectedText()` (`tempModel`), `insertLine()` (`text_model`),
`generateSnippetEvent()` (`content_model`).

## Что проверялось и оказалось ни при чём

- **Метаданные.** За 7 обращений к разным объектам 1С прислала 65 тыс. символов, `window.bslMetadata`
  вырос с 500 169 до 528 093 символов (+56 КБ). Сотен мегабайт там нет.
- **Сами подсказки.** 40 глобальных (`CTRL+Пробел`) — −12 МБ, 80 по платформенным типам
  (`Массив.`, `ТаблицаЗначений.`) — +9 МБ, то есть шум.
- **Правки без пауз.** 20 секунд автоповтора `Enter` — −27 МБ: дебаунс схлопывает очередь.
